### 🛠 Методология и ход выполнения работы

#### 1. Инициализация и системный интерфейс оснастки

Для развертывания управляющей консоли использовалась встроенная системная команда:

* **Директива запуска:** Комбинация клавиш `Win + R` $\rightarrow$ ввод исполняемого файла `gpedit.msc` с подтверждением прав администратора.
* **Архитектура интерфейса:** Окно представляет собой классическую консоль управления MMC (Microsoft Management Console). Левый сегмент графического экрана отображает древовидную иерархию каталогов и вложенных контейнеров, правый — детализирует конкретные параметры, их описания и текущие системные статусы.

#### 2. Логическое разделение и приоритеты конфигураций

В ходе анализа структуры GPO были подробно изучены два корневых узла управления:

* **Конфигурация компьютера:** Данный блок содержит параметры, которые жестко применяются на аппаратном уровне к самой операционной системе. Действие этих политик распространяется на рабочую станцию в целом, независимо от того, какая учетная запись выполнила вход (инициализируются на этапе загрузки ядра ОС до экрана авторизации).
* **Конфигурация пользователя:** Настройки данного контейнера привязаны к конкретным учетным записям. Они активируются непосредственно в момент прохождения процедуры авторизации пользователя и регулируют его персональную рабочую среду (интерфейс, доступ к утилитам, параметры проводника).

#### 3. Практический алгоритм модификации параметров

* Поиск целевых директив осуществлялся путем последовательного раскрытия контейнеров («Административные шаблоны», «Система», «Компоненты Windows»).
* В процессе аудита параметров анализировались три базовых состояния политик: *«Не задано»* (штатное поведение по умолчанию), *«Включено»* (принудительная активация ограничения или функции) и *«Отключено»* (жесткий запрет на исполнение процесса).
* **Взаимосвязь с системным реестром:** Была изучена низкоуровневая природа групповых политик. Любое изменение в консоли `gpedit.msc` физически перезаписывает двоичные ключи в конфигурационных файлах реестра. Например, управление системным «Диалогом слежения за завершением работы» (Shutdown Event Tracker) технически дублируется в реестре путем создания DWORD-параметров по защищенному пути: `HKLM\Software\Policies\Microsoft\Windows NT\Reliability`.

### 📊 Топология структуры локальных политик (GPO)

| Корневой раздел | Ключевые подразделы | Назначение и контролируемые функции |
| --- | --- | --- |
| **Конфигурация компьютера** | Конфигурация Windows $\rightarrow$ Параметры безопасности | Настройка политик паролей, блокировки учетных записей, брандмауэра и прав назначения служб. |
|  | Административные шаблоны $\rightarrow$ Система | Управление загрузкой, электропитанием, механизмами восстановления и доступом к внешним накопителям. |
| **Конфигурация пользователя** | Административные шаблоны $\rightarrow$ Панель управления | Ограничение доступа к настройкам экрана, апплетам системы и блокировка запуска диспетчера задач. |
|  | Административные шаблоны $\rightarrow$ Рабочий стол | Кастомизация интерфейса, скрытие системных ярлыков, запрет на изменение структуры меню «Пуск». |

### ❓ Ответы на контрольные вопросы

**1. Что такое групповые политики (GPO) и какова их главная цель в инфраструктуре ПК?**

 Групповые политики — это встроенный инструмент операционных систем Microsoft Windows, представляющий собой набор правил и параметров, с помощью которых осуществляется централизованная настройка операционной системы, рабочей среды и программного обеспечения. Главная цель GPO — автоматизация администрирования, стандартизация пользовательских мест, обеспечение информационной безопасности и ограничение доступа пользователей к критически важным функциям ОС для предотвращения сбоев.

**2. На какие базовые категории разделяются объекты групповых политик и в чем их отличие?**

 Все объекты групповых политик строго разделены на две категории:
 * **Конфигурация компьютера (Computer Configuration):** Применяется непосредственно к операционной системе и железу компьютера. Эти политики имеют наивысший приоритет, срабатывают первыми при включении ПК и действуют абсолютно на всех пользователей, работающих за этой машиной.
 * **Конфигурация пользователя (User Configuration):** Привязана к конкретному профилю пользователя. Эти настройки активируются позже (после ввода пароля на экране приветствия) и формируют персональные ограничения среды для конкретного человека, не влияя на учетную запись администратора. 

**3. Опишите внутреннее устройство подраздела «Административные шаблоны» (Administrative Templates).**

 Раздел «Административные шаблоны» представляет собой структурированную базу данных, состоящую из текстовых файлов с расширениями `.admx` (и языковых пакетов `.adml`), в которых прописаны понятные человеку правила и интерфейсы для управления параметрами реестра. Этот раздел содержит тысячи настроек, разделенных по категориям (Компоненты Windows, Сеть, Панель управления, Пуск и Панель задач), позволяя включать или отключать системные функции без необходимости ручного поиска и редактирования шестнадцатеричных ключей в `regedit`.

**4. С помощью какой системной команды осуществляется инициализация Редактора локальных политик?**

 Инициализация и запуск консоли управления осуществляются путем ввода служебной команды `gpedit.msc` в диалоговом окне «Выполнить» (`Win + R`) или через административный интерфейс командной строки. Стоит отметить, что данная оснастка по умолчанию доступна только в старших редакциях операционной системы (Windows Pro, Enterprise, Education) и отсутствует в базовой Home-версии.
