### 🎯 Цель работы

Изучение алгоритмов локализации программных конфликтов в среде Windows 10 с помощью механизма «чистой загрузки» (Clean Boot). Практическое освоение низкоуровневой консольной утилиты SFC (System File Checker) для контроля целостности, обнаружения деструктивных изменений и автоматического восстановления критически важных компонентов операционной системы.

### 🛠 Методология и ход выполнения работы

#### Этап 1. Конфигурация изолированной программной среды (Чистая загрузка)

Для исключения влияния стороннего софта, фоновых процессов и драйверов на стабильность ОС была выполнена процедура Clean Boot:

1. Посредством диалогового окна «Выполнить» (`Win + R`) осуществлен запуск конфигуратора `msconfig` с правами локального администратора.
2. В разделе **«Общие»** активирован селектор *«Выборочный запуск»*, при этом отключена директива автоматического развертывания элементов автозапуска.
3. В разделе **«Службы»** применен фильтр *«Не отображать службы Майкрософт»* для защиты базовых функций ядра (сетевой стек, Plug and Play, аудит событий), после чего сторонние фоновые службы были переведены в состояние *«Отключено»*.
4. Выполнена плановая перезагрузка рабочей станции для инициализации чистой сессии операционной системы.

---

#### Этап 2. Инструментальный контроль и восстановление файлов (Консоль SFC)

После загрузки системы в изолированном режиме была запущена интерактивная командная строка (`cmd.exe`) с наивысшими привилегиями для выполнения сканирования.

* **Запущенная команда:** `sfc /scannow`
* **Процесс выполнения:** Утилита выполнила побитовую сверку цифровых подписей и хэш-сумм защищенных системных библиотек в каталоге `System32` с эталонными копиями из изолированного хранилища компонентов (WinSxS).

**Зафиксированный результат сканирования (на основе данных консоли):**

> *«Программа защиты ресурсов Windows обнаружила поврежденные файлы и успешно их восстановила. Подробные сведения см. в файле CBS.Log, который находится по следующему пути: %windir%\Logs\CBS\CBS.log»*.

Это подтверждает, что в системе присутствовали локальные нарушения целостности (вызванные программными сбоями или некорректным завершением процессов), которые были полностью устранены в автоматическом режиме.

### ❓ Ответы на контрольные вопросы

**1. Почему команда Sfc не смогла выполнить проверку созданного пользователем файла sfccommand.txt?**

> Консольная утилита `sfc` (System File Checker) жестко ограничена встроенной базой манифестов защиты ресурсов Windows (WRP — Windows Resource Protection). Она предназначена исключительно для мониторинга критических системных компонентов (библиотек `.dll`, исполняемых модулей `.exe`, файлов конфигурации драйверов), входящих в состав дистрибутива ОС. Пользовательские файлы, текстовые документы и сторонний прикладной софт не имеют цифровых подписей WRP и записей в реестре компонентов, поэтому игнорируются утилитой.

**2. С какими дополнительными параметрами и флагами можно использовать команду sfc в консоли?**

> Согласно встроенной справке, утилита поддерживает следующие основные аргументы командной строки:
> * `/scannow` — Полномасштабное сканирование всех защищенных ресурсов с немедленным восстановлением поврежденных элементов.
> * `/verifyonly` — Изолированный мониторинг целостности без внесения изменений в файловую систему (только фиксация ошибок).
> * `/scanfile=<путь>` — Точечное сканирование и восстановление конкретного указанного системного файла.
> * `/verifyfile=<путь>` — Локальная проверка указанного файла без его автоматического исправления.
> * `/offbootdir=<буква>` — Указание пути к корневому каталогу загрузки при восстановлении автономной (неактивной в данный момент) ОС.
> * `/offwindir=<путь>` — Указание пути к каталогу Windows для автономного сканирования (например, из среды восстановления RE).
> 
> 

**3. В каких практических ситуациях и для каких целей администратору необходимо задействовать механизм «чистой загрузки»?**

> Инициализация операционной системы через Clean Boot требуется в следующих случаях:
> * **Поиск программных конфликтов:** Когда операционная система или конкретное приложение работают нестабильно (вылетают, вызывают синий экран BSOD) из-за скрытого противодействия фонового софта, антивирусов, твикеров или служб автозагрузки.
> * **Проблемы с инсталляцией софта:** Если сторонние фоновые процессы блокируют установку или корректное обновление крупных программных комплексов и драйверов.
> * **Диагностика производительности:** Для выявления служб, которые чрезмерно нагружают центральный процессор, накопитель или оперативную память в фоновом режиме.
