# Лабораторная работа: Docker Compose — HomeHub

## Цель работы

Развернуть оригинальный HomeHub с помощью Docker Compose, настроить семейную панель, изучить хранение данных, проверку состояния и удаление контейнерного проекта.

Работа выполнена по [инструкции преподавателя](https://github.com/rurewa/imfua/blob/main/content/Docker/DockerCompose/Homehub.md), прочитанной полностью, включая раздел удаления. Используется [оригинальный HomeHub](https://github.com/surajverma/homehub) и образ `ghcr.io/surajverma/homehub:latest`.

## Что такое HomeHub и Docker Compose

**HomeHub** — семейное веб-приложение для общих заметок, покупок, домашних дел, календаря, файлов, рецептов и учёта расходов. В оригинальном проекте используются Flask и SQLite.

**Docker Compose** — инструмент описания и запуска контейнеров через YAML-файл. В этой работе он запускает один сервис HomeHub, задаёт порт, переменные окружения и подключения локальных каталогов. Отдельная база данных и дополнительные сервисы не нужны.

## Подготовка и структура

Проверены `main` и ветка предыдущей работы `lab/docker-compose`: готового развёртывания HomeHub нет. Файл `content/Docker/DockerCompose/Homehub.md` — учебная инструкция, а не выполненная лабораторная. Новая ветка `lab/docker-compose-homehub` создана от `main`. Предыдущая работа не изменяется.


Команда скачивает исходный репозиторий в отдельный каталог для изучения. Изучены `README.md`, `compose.yml`, `Dockerfile`, `config-example.yml` и код загрузки настроек. Исходный коммит: `fb33d56b949f4dc984a5e556c862ab103858911a`. В оригинале есть `app/`, `templates/`, `static/`, `tests/`, `docs/`, `translations/` и точки входа `run.py`/`wsgi.py`.

Для лабораторной используется готовый образ, поэтому полная копия стороннего репозитория, его Git-история и Dockerfile в работу не добавлены.

## Содержимое compose.yml

Файл перенесён из образца преподавателя:

```yaml
# compose.yml
services:
  homehub:
    container_name: homehub
    image: ghcr.io/surajverma/homehub:latest
    ports:
      - "5000:5000" #app listens internally on port 5000
    environment:
      - FLASK_ENV=production
      - SECRET_KEY=${SECRET_KEY:-} # set via .env; falls back to random if not provided
    volumes:
      - ./uploads:/app/uploads
      - ./media:/app/media
      - ./pdfs:/app/pdfs
      - ./data:/app/data
      - ./config.yml:/app/config.yml:ro
```

| Параметр | Назначение |
| --- | --- |
| `services.homehub` | Единственный сервис приложения |
| `container_name: homehub` | Фиксированное имя контейнера |
| `image` | Оригинальный готовый образ из GitHub Container Registry |
| `5000:5000` | Порт 5000 компьютера направляется на порт 5000 контейнера |
| `FLASK_ENV=production` | Значение окружения из образца преподавателя |
| `SECRET_KEY=${SECRET_KEY:-}` | Ключ берётся из окружения или локального .env; при отсутствии передаётся пустая строка |
| `uploads` → `/app/uploads` | Загруженные пользователями файлы |
| `media` → `/app/media` | Медиафайлы |
| `pdfs` → `/app/pdfs` | PDF-файлы |
| `data` → `/app/data` | База данных и служебные данные |
| `config.yml` → `/app/config.yml:ro` | Настройки доступны контейнеру только для чтения |

Это bind mounts: данные находятся в каталогах компьютера и сохраняются после удаления контейнера. В изученном исходном коде HomeHub пустой `SECRET_KEY` приводит к созданию ключа в `data/secret_key`. Для демонстрации ниже предлагается задать собственный ключ локально. Значение переменной оболочки имеет приоритет над `.env`.

## Настройки config.yml

Файл полностью повторяет YAML-блок преподавателя, включая комментарии и значения.

- `instance_name: "My Home Hub"` — название панели.
- `password: ""` — доступ без общего пароля, как в учебном примере.
- `admin_name: "Administrator"` — имя администратора.
- `family_members` — Mom, Dad, Dipanshu, Vivek, India.
- `feature_toggles` — все 13 функций из образца имеют значение `true`.

| Функция | Для чего нужна |

| `shopping_list` | Список покупок |

В `reminders` оставлены `time_format: 12h` и `calendar_start_day: monday`: время в 12-часовом формате, неделя начинается с понедельника.

## Запуск в Windows через VS Code и Docker Desktop

1. Установите Git, VS Code и Docker Desktop. Запустите Docker Desktop, используйте Linux containers с WSL 2 и дождитесь готовности движка.
2. Откройте PowerShell в папке для учебных проектов. Если репозиторий ещё не скачан, выполните:

```powershell
git clone https://github.com/d1p3r666/522.git
cd 522
git switch lab/docker-compose-homehub
code .
```

`git clone` скачивает ваш репозиторий; `cd` переходит в него; `git switch` выбирает ветку лабораторной; `code .` открывает текущую папку в VS Code. В существующей копии репозитория вместо повторного клонирования выполните `git fetch origin` (получить сведения об удалённых ветках) и `git switch lab/docker-compose-homehub`.

3. В VS Code откройте Terminal → New Terminal и выберите PowerShell. Из корня репозитория перейдите именно в каталог этой работы:

```powershell
cd DockerCompose/HomeHub
docker version
docker compose version
```

`cd` задаёт рабочий каталог. Все следующие Docker-команды выполняются здесь, чтобы не выбрать Compose-файл предыдущей работы. `docker version` проверяет клиент и доступность сервера; `docker compose version` — наличие Compose.

4. Подготовьте локальный файл окружения (один раз, если `.env` ещё не существует):

```powershell
Copy-Item .env.example .env
$keyBytes = New-Object byte[] 32
[System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($keyBytes)
('SECRET_KEY=' + [Convert]::ToBase64String($keyBytes)) | Set-Content -Encoding ascii .env
```

`Copy-Item` создаёт локальную копию шаблона; следующие строки генерируют 32 случайных байта и записывают ключ в `.env`, не выводя его на экран. Не повторяйте эти команды поверх существующего ключа. `.env.example` не содержит реального секрета.

Каталоги уже присутствуют в репозитории. Если они отсутствуют в вашей копии, восстановите их:

```powershell
New-Item -ItemType Directory -Force uploads, media, pdfs, data
```

`New-Item` создаёт каталоги данных; `-Force` позволяет использовать уже существующие папки, не удаляя их содержимое. Убедитесь в проводнике VS Code, что `config.yml` — файл.

5. Проверьте настройки и запустите контейнер:

```powershell
docker compose config
docker compose up -d
docker compose ps
docker compose logs --tail=100
```

`config` проверяет и показывает итоговую конфигурацию. Она включает ключ из окружения, поэтому такой вывод с настоящим ключом не публикуйте. `up -d` получает образ при необходимости, создаёт сеть и контейнер и запускает его в фоне. `ps` показывает состояние и порты. `logs --tail=100` показывает последние 100 строк журналов. Первое скачивание и запуск могут занять несколько минут.

Если имя `homehub` или порт 5000 уже заняты, сначала выясните, какой проект их использует; чужие контейнеры не удаляйте.

6. Откройте веб-интерфейс: [http://localhost:5000](http://localhost:5000).

Выберите демонстрационного члена семьи, откройте заметки и список покупок, добавьте тестовые записи и обновите страницу. Проверьте календарь с понедельником и категориями Health, Bills, School, Family. Остальные функции из таблицы должны быть включены. Это сценарий проверки на компьютере студента; в текущей среде он не выполнен.

Для демонстрации сохранности данных после добавления записи:

```powershell
docker compose down
docker compose up -d
```

`down` останавливает и удаляет контейнер и сеть проекта, сохраняя локальные каталоги. Повторный `up -d` создаёт контейнер с теми же данными. Убедитесь в браузере, что запись сохранилась.

## Остановка и удаление

Обычная остановка без удаления контейнера:

```powershell
docker compose stop
```

`stop` останавливает сервис; контейнер и данные сохраняются.

Команды из раздела удаления преподавателя:

| Команда | Назначение и влияние |
| --- | --- |
| `docker compose down -v` | Останавливает и удаляет контейнеры и сеть проекта, а также его объявленные именованные и подключённые анонимные тома. В этой работе таких томов нет: bind mounts uploads, media, pdfs, data остаются на диске |
| `docker ps -a` | После удаления позволяет проверить общий список контейнеров |
| `docker compose ps -a` | Позволяет проверить, остались ли контейнеры текущего проекта |
| `docker images` | Позволяет найти точный образ HomeHub |
| `docker rmi ghcr.io/surajverma/homehub:latest` | Удаляет локальный тег/образ HomeHub, если Docker разрешает удаление; это конкретный вариант команды преподавателя `docker rmi id-образа` |
| `docker compose down --rmi all -v` | Вместе с контейнером, сетью и томами проекта пытается удалить используемые сервисами образы; bind mounts остаются |

Удаление образа выполняйте только для собственного тестового HomeHub, убедившись, что образ не нужен другим проектам. Не используйте принудительное удаление и общую очистку Docker.

Преподаватель также приводит `cd ..` (выход в родительскую папку) и `rm -rf homehub` (рекурсивное удаление клона в Unix). Последняя команда удаляет и локальные данные внутри папки. Для сдачи этой работы удалять каталог `DockerCompose/HomeHub` не требуется. В PowerShell `rm -rf` не является переносимым эквивалентом Unix-команды. Удаление каталогов здесь не выполнялось.

Перед удалением любых локальных данных остановите приложение и сохраните нужные файлы. Деструктивные команды в текущей среде не запускались.
