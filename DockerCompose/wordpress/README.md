# WordPress и MySQL через Docker Compose

Лабораторная работа по [инструкции преподавателя](https://github.com/rurewa/imfua/blob/main/content/Docker/DockerCompose/WordPress.md).
Проект расположен в `DockerCompose/wordpress` репозитория `d1p3r666/522`.

## Запуск

Нужны Docker Desktop с запущенным Linux Engine, Docker Compose и свободный порт 8081.
Все команды ниже выполняются в каталоге этого README.

1. Проверьте существующие приложения: `docker compose ls` и `docker ps`.
   Не останавливайте чужие контейнеры. Если порт 8081 занят, сначала выясните, каким приложением.
2. Если `.env` отсутствует, скопируйте шаблон: `Copy-Item .env.example .env` (PowerShell)
   или `cp .env.example .env` (Bash). Задайте два разных случайных пароля.
   При первоначальном выполнении работы локальный `.env` создаётся автоматически;
   существующий файл перезаписывать не нужно.
3. Проверьте конфигурацию и запустите проект:

   ```shell
   docker compose config --quiet
   docker compose up -d
   docker compose ps -a
   docker compose logs --tail=100 db wordpress
   ```

4. Откройте <http://localhost:8081>. При первом запуске MySQL может инициализироваться несколько минут.

`.env` содержит настоящие локальные пароли и исключён из Git. `.env.example` содержит только шаблоны.
WordPress и MySQL получают пароль пользователя `wordpress` из одной переменной `MYSQL_PASSWORD`.
После создания тома изменение `.env` само по себе не меняет пароль уже существующего пользователя MySQL.

## Настройка в браузере

В локальном проекте установка уже выполнена: язык — русский, название сайта —
«Лабораторная работа — WordPress», администратор — `user`.
Откройте <http://localhost:8081/wp-admin/>. Случайный пароль сохранён только в
локальном `.env` в переменной `WORDPRESS_ADMIN_PASSWORD`.
Учебный email `student@example.test` можно заменить своим в настройках WordPress.
Проходить мастер установки повторно не требуется.

При развёртывании на новом компьютере с пустыми томами выберите язык, укажите
название сайта, логин, пароль и email, затем нажмите «Установить WordPress».
Учётная запись администратора сайта отличается от пользователя базы данных;
переменные `WORDPRESS_ADMIN_*` в локальном `.env` служат для хранения доступа,
а сама учётная запись уже создана мастером установки и хранится в MySQL.

## Параметры Compose

| Параметр | Назначение |
| --- | --- |
| `services.db`, `mysql:8.0` | Официальный MySQL 8.0, база и пользователь `wordpress` |
| `services.wordpress`, `wordpress:apache` | Официальный WordPress с Apache; вариант Apache указан явно вместо `latest` из примера |
| `ports: 8081:80` | Доступ к Apache через порт 8081 компьютера |
| `environment` | Создание базы и передача WordPress согласованных параметров подключения |
| `WORDPRESS_DB_HOST: db:3306` | Доступ к MySQL по DNS-имени сервиса в сети Compose |
| `wp-network` | Общая изолированная сеть двух сервисов |
| `db_data:/var/lib/mysql` | Постоянное хранение базы данных |
| `wordpress_data:/var/www/html` | Постоянное хранение всех файлов WordPress, включая темы, плагины и загрузки |
| `restart: unless-stopped` | Автоматический перезапуск, кроме явно остановленных контейнеров |
| `healthcheck`, `depends_on` | WordPress запускается после положительной проверки готовности MySQL |

Compose добавляет имя проекта к именам сети и томов (обычно `wordpress_wp-network`,
`wordpress_db_data`, `wordpress_wordpress_data`), чтобы не смешивать ресурсы разных проектов.
Порт MySQL на компьютер не публикуется: он доступен WordPress внутри сети.

## Управление и проверка

```shell
docker compose logs -f wordpress
docker compose logs -f db
```

Выход из просмотра логов: Ctrl+C. Для разового просмотра используйте `--tail=100` вместо `-f`.

```shell
docker compose stop
docker compose ps -a
docker compose start
docker compose restart
docker compose config --quiet
docker compose ps -a
```

После проверки оставьте оба сервиса запущенными. `docker compose config` выводит полную
конфигурацию, включая подставленные пароли; для безопасной проверки используйте `--quiet`.
Не публикуйте полный вывод с паролями и не включайте его в скриншоты.
Команды остановки и перезапуска сохраняют тома. Удаление проекта из последнего раздела
инструкции преподавателя здесь не выполняется: для сдачи нужен работающий проект с данными.

## Сохранение в Git

Из корня репозитория `522`:

```shell
git add DockerCompose/wordpress/compose.yaml DockerCompose/wordpress/README.md DockerCompose/wordpress/.gitignore DockerCompose/wordpress/.env.example
git add DockerCompose/wordpress/REPORT.md DockerCompose/wordpress/screenshots
git diff --cached --check
git diff --cached --stat
git commit -m "Add WordPress and MySQL Docker Compose lab"
```

Перед коммитом убедитесь, что `.env` отсутствует в списке индексированных файлов.
Отправлять изменения следует только в свой репозиторий, а не в репозиторий преподавателя.
